## 3. Historical PIT 상태 구조

```
FilingRegistry(원천 수정) + XBRL 캐시
  └ b_select_core_oi_1q_pit.evaluate_pit_signals   ← V03 FIX01과 같은 판정기(src 공유), 캐시만 사용
      └ b_select_core_fundamental_status
          ├ 상태 기준일: 거래·보유·청산대기 = entry_signal_date / 진입대기 = pending signal_date / 신호 없는 항목 = requested_as_of
          ├ classify_evaluation_row → 우수/양호/보통/주의/미상
          └ ledger (ticker, ISU_CD, status_asof_date) — 확정 상태는 다시 쓰지 않음, 캐시 공백 미상만 다시 판정
              └ export_strategy_monitor_web: 현재 항목 + 거래 이력의 fundamental_status
                  ├ 전략 운용 현재 상태 / Select Core 리스트 / 필터
                  ├ 거래 이력 열 / 필터
                  └ 종목 리포트 현재 판단 카드
```

- **판정 규칙**: V01과 같습니다.
  - 우수: 최신 공개 분기 영업이익 ≥ 20억, 전년동기와 비교 가능, 현재 > 전년동기
  - 양호: 0 < 영업이익 < 20억, 비교 가능, 현재 > 전년동기
  - 보통: 그 밖의 흑자
  - 주의: 영업이익 ≤ 0
  - 미상: 판정 불가
- **신호 없는 관찰·기타 항목**: w.md에 규정이 없어서 `requested_as_of`(9-25) PIT로 판정했습니다. 기준일 근거(basis)는 `REQUESTED_AS_OF_NO_SIGNAL`로 기록합니다.
- **고정성**: 판정은 그 날짜까지 공개된 공시만 읽으므로, 같은 키는 나중에 다시 계산해도 같은 결과입니다. ledger는 이 결과를 저장해 두는 속도용 캐시입니다.
  - 확정 상태가 바뀌려 하면 예외로 막습니다(테스트로 확인).
- **exporter 동작**: ledger를 읽기만 하고 파일은 쓰지 않습니다. ledger에 없는 키(새 날짜)는 메모리에서 같은 판정기로 계산합니다.
  - 9-25 기준: 1,739키, 1.3초
  - 새 날짜의 관찰 항목 약 1,450키: 약 6분
