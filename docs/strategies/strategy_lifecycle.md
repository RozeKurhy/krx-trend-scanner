# 전략 생애주기와 채택 절차

이 문서는 새로운 전략을 추가하거나 기존 전략을 개선할 때 공통으로 사용하는
전략 검증 및 운영 절차다. 특정 전략에 종속되지 않으며, 전략별 규칙과 결과는
각 전략의 문서와 연구 결과물에 별도로 보존한다.

## 공식 전략과 기본 전략

**공식 전략**은 정해진 검증을 통과하여 프로젝트에서 사용할 수 있다고 인정된
전략이다. 공식 전략은 여러 개가 동시에 존재할 수 있다.

**기본 전략**은 공식 전략 중 현재 프로젝트에서 우선적으로 사용하는 대표
전략이다. 새로운 전략이 공식 전략으로 채택되었다고 해서 자동으로 기본 전략이
되지는 않는다. 기존 기본 전략보다 프로젝트 목적에 더 적합하고 전체적으로
명확한 우위가 있을 때 별도의 승격 절차를 거쳐 변경한다.

## 전략 생애주기

각 단계의 목적을 확인하고, 앞 단계의 결론과 기록을 바탕으로 다음 단계로
진행한다.

1. **전략 아이디어 정의** — 해결하려는 문제와 기대하는 개선점을 분명히 한다.
2. **전략 규칙 명세화** — 진입, 보유, 청산, 재진입, 신호, 체결 규칙을 문서로 확정한다.
3. **후보 전략 동결** — 검증을 시작하기 전에 변경할 규칙과 변경하지 않을 규칙을 고정한다.
4. **검증 계획 확정** — 비교 대상, 데이터, 기간, 평가 지표, 판단 기준을 사전에 정한다.
5. **동일 조건 비교 백테스트** — 변경된 요소만 다르게 하여 기존 전략과 후보 전략을 비교한다.
6. **핵심 성과 비교** — 수익성, 손실 위험, 낙폭, 거래와 보유 특성을 함께 비교한다.
7. **실패 사례 및 부작용 검증** — 평균값에 가려진 큰 손실, 빠른 청산, 큰 수익 종목 훼손, 장기 보유를 확인한다.
8. **강건성 검증** — 결과가 특정 시기, 종목, 표본에만 의존하는지 변경 규모와 위험도에 맞게 확인한다.
9. **최종 전략 검토** — 성과와 약점, 전략 목적과의 적합성, 교환 관계를 종합해 검토한다.
10. **공식 전략 채택 여부 결정** — 채택, 수정 후 재검증, 보류, 폐기 중 하나를 결정하고 근거를 남긴다.
11. **기본 전략 승격 여부 결정** — 공식 전략 채택과 별도로 기존 기본 전략 교체 필요성을 판단한다.
12. **버전·문서·결과물 확정** — 최종 규칙, 검증 계획, 결과, 결정 기록을 해당 버전으로 보존한다.
13. **운영 환경 반영** — 채택된 전략만 승인된 범위에서 운영 환경과 보고서에 반영한다.
14. **사후 성과 확인** — 실제 운영 결과를 검증 결과와 비교하고 예상 밖의 문제를 기록한다.

## 후보 전략 동결

검증을 시작하기 전에 다음 항목을 확정한다.

- 진입 규칙
- 보유 규칙
- 청산 규칙
- 재진입 규칙이 있다면 해당 규칙
- 신호 발생 시점과 체결 시점
- 비교 대상 전략
- 검증 기간과 검증 대상
- 주요 평가 항목

동결 이후 결과를 보고 더 유리하도록 규칙을 바꾸면 같은 후보의 검증을
이어가는 것이 아니다. 변경된 규칙은 새로운 후보 전략으로 다시 동결하고
검증한다.

## 검증 계획 사전 확정

백테스트를 실행하기 전에 다음을 문서로 정한다.

- 무엇과 비교하는가
- 어떤 데이터와 기간을 사용하는가
- 동일 조건 비교를 어떻게 보장하는가
- 어떤 지표를 평가하는가
- 어떤 결과이면 채택, 보류, 수정 후 재검증, 폐기할 것인가

전략별 세부 수치와 합격 기준은 각 전략의 검증 계획에서 정한다. 공통 절차
문서에는 특정 전략의 고정 임계값을 넣지 않는다. 결과를 확인한 뒤 합격 기준을
바꾸지 않는다.

## 전체 백테스트 성능 사전 점검

모든 전체 백테스트는 동일한 실제 실행 경로로 대표 샘플을 먼저 실행한다. 샘플에서 실제 경과시간, CPU, RSS와 고정 초기화 비용·반복 처리 비용을 측정하고, 이를 바탕으로 전체 예상 실행시간을 산출한다. 일반적인 전체 백테스트는 약 1시간을 목표로 하며 가능하면 1시간 30분 이내 완료를 지향한다. 다만 새로운 전략 특성상 더 오래 걸릴 수 있으므로 90분 자체를 정확성 실패 기준으로 사용하지 않는다. 반복적인 전략 연구에서는 전체 백테스트가 2시간 이상 걸리는 상태를 기본 실행 방식으로 두지 않는다. 기존 성능 기록이나 유사 백테스트와 비교해 예상시간이 비정상적으로 길면 전체 실행을 시작하지 않고 중복 계산, 캐시 재사용, 기존 병렬화 구조의 병목을 먼저 확인한다. 이 샘플은 결과 최적화나 매개변수 조정이 아니라 실행 성능과 정상 동작 확인만을 위한 것이다.

## 동일 조건 비교 원칙

개선판을 검증할 때는 기존 전략과 후보 전략 사이에서 변경된 요소만 다르게
한다. 예를 들어 청산 규칙을 개선하는 경우 진입 조건과 진입 시점은 동일하게
유지한다. 진입 규칙을 개선하는 경우에도 나머지 비교 조건은 가능한 한
동일하게 유지한다.

여러 요소를 한꺼번에 변경하여 결과 차이의 원인을 알 수 없는 비교는 피한다.
후보가 기존 전략과 다른 표본을 만들었다면, 표본 차이와 규칙 효과를 분리해
기록한다.

## 평가 영역

전략의 목적과 교환 관계를 판단하기 위해 최소한 다음을 함께 검토한다.

- 수익성
- 손실 위험과 큰 손실 억제 능력
- 최대 낙폭
- 큰 수익 종목 보존 능력
- 보유 기간과 자본이 장기간 묶이는 문제
- 거래 빈도와 회전율
- 특정 시기나 특정 종목 의존도
- 기존 전략 대비 개선점과 악화점

모든 항목에서 반드시 우수해야 하는 것은 아니다. 전략의 우선 목적에 맞는
개선인지, 어떤 대가를 치르는지 함께 판단한다.

## 실패 사례와 부작용 검증

평균 수익률 하나만으로 전략을 채택하지 않는다. 다음 사례를 별도로 확인한다.

- 큰 손실 사례
- 예상하지 못한 장기 보유
- 지나치게 빠른 청산
- 큰 수익 종목 훼손
- 특정 시장 상황에서의 급격한 성능 저하
- 전략 의도와 실제 결과가 다른 사례

문제가 발견되어도 즉시 규칙을 보완하지 않는다. 실제 전략 품질에 의미 있는
문제인지 먼저 판단하고, 규칙을 바꾸는 경우에는 새로운 후보로 동결하여
재검증한다.

## 강건성 검증

강건성 검증은 후보 전략이 특정 표본에 우연히 맞은 것이 아닌지 확인하는
단계다. 변경 규모와 위험도에 맞는 필요한 수준까지만 수행한다.

불필요한 대규모 경우의 수 탐색, 무제한 매개변수 최적화, 결과가 좋아질 때까지
반복하는 조정은 하지 않는다. 검증 범위와 한계를 결과 기록에 함께 남긴다.

## 공식 전략 채택과 기본 전략 승격

검증을 통과한 후보는 공식 전략으로 채택할 수 있다. 채택 시 다음을 남긴다.

- 전략 이름과 버전
- 최종 규칙 문서
- 검증 결과
- 기존 전략과의 핵심 차이
- 채택 결정과 이유
- 알려진 약점과 교환 관계

기본 전략 승격은 별도로 판단한다. 후보 공식 전략이 기존 기본 전략보다
프로젝트 목적에 더 적합하고 전체적으로 명확한 우위가 있을 때만 승격한다.
일부 지표 하나가 좋아졌다는 이유만으로 기본 전략을 교체하지 않는다.

기본 전략을 변경할 때는 이전 기본 전략, 새 기본 전략, 변경 이유, 핵심 비교
결과, 적용 시점을 명확하게 남긴다. 이전 전략의 문서와 검증 기록은 삭제하지
않는다.

## 검증 결과 처리

검증 결과는 다음 네 가지 중 하나로 처리한다.

- **공식 전략 채택** — 검증을 통과하여 공식 전략으로 인정한다.
- **수정 후 재검증** — 아이디어는 유효하지만 규칙 수정이 필요하다. 수정된 규칙은 새로운 후보로 다시 동결한다.
- **보류** — 현재 자료만으로 판단하기 어렵거나 추가 데이터가 필요하다.
- **폐기** — 의미 있는 개선이 없거나 부작용이 더 크다.

폐기된 결과도 연구 기록으로 남길 수 있지만, 현재 기준 문서와 혼동되지
않도록 상태와 적용 범위를 분명히 표시한다.

## 문서 관리와 과도한 절차 방지

`strategy_lifecycle.md`는 전략마다 복사하지 않고 프로젝트 전체에서 하나만
유지한다. 전략별 규칙, 검증 계획, 백테스트 결과, 검증 결과, 채택 또는 폐기
결정은 각 전략의 기록으로 별도 보존한다.

이 공통 문서는 전략 채택 절차가 실제로 변경될 때만 수정한다. 과거 전략의
검증 결과를 나중에 현재 기준에 맞게 임의로 다시 쓰지 않는다.

이 절차의 목적은 세 가지다.

1. 매번 검증 절차를 처음부터 다시 설계하지 않는다.
2. 결과를 보고 기준을 임의로 바꾸지 않는다.
3. 전략이 채택되거나 탈락한 이유를 나중에도 이해할 수 있게 한다.

필요한 검증만 수행하고 명확한 결론이 나오면 다음 단계로 진행한다. 이 문서는
전략 연구를 불필요하게 느리게 만드는 규정집이 아니다.
