# 패턴 생애주기와 공식 채택 기준

이 문서는 새 패턴을 연구 후보에서 공식 패턴으로 채택하거나, 보류·종료할 때 공통으로 쓰는
기준과 절차다. 특정 패턴에 종속되지 않으며, 패턴별 산식·규칙·검증 결과는 각 패턴 폴더의
문서에 따로 보존한다.

## 패턴과 전략의 구분

패턴은 **무엇이 보이는가, 어떤 상태인가**를 정의한다. 전략은 **그 상태를 보고 무엇을 할
것인가**를 정의한다.

| 구분 | 다루는 공식성 | 기준 문서 |
|---|---|---|
| 패턴 생애주기 | 상태·구조 판단 모델의 공식성 | 이 문서 |
| 전략 생애주기 | 진입·보유·청산 행동 규칙의 공식성 | [전략 생애주기와 채택 절차](../strategies/strategy_lifecycle.md) |

그래서 패턴의 공식 채택은 투자 성과가 아니라 의미, 계약, 재현성, 검증, 차별성, 현재
권위를 본다. 수익률, 최대 낙폭, 손실 억제는 패턴 자체의 채택 기준이 아니며 전략 영역에서
평가한다.

공식 패턴이라고 해서 공식 전략이 되거나, 수익성이 확인되었거나, 매수 추천을 뜻하지 않는다.

## 생애주기 상태

| 상태 | 뜻 | 운영 권위 |
|---|---|---|
| 연구 후보 (`RESEARCH_CANDIDATE`) | 연구·설계·검증 중이다 | 없음 |
| 공식 패턴 (`OFFICIAL_PATTERN`) | 공식 채택 기준 6개를 충족하고 현재 권위가 확정되었다 | 있음 |
| 보류 (`DEFERRED`) | 아이디어는 유지하지만 현재 자료나 필요성으로는 채택 판단을 미룬다 | 없음 |
| 종료 (`RETIRED`) | 더 이상 현재 패턴으로 쓰지 않는다. 역사 기록은 보존한다 | 없음 |

- 연구 후보는 공식 패턴, 보류, 종료 중 하나로 결정한다.
- 보류된 패턴은 새 자료나 필요가 생기면 연구 후보로 다시 연다. 더 이상 필요 없으면 종료한다.
- 공식 패턴을 더 쓰지 않게 되면 종료한다. 공식 패턴의 새 버전은 연구 후보로 따로 진행하며,
  채택되기 전까지 기존 공식 버전이 현재 권위를 유지한다.
- 결과를 보고 규칙을 고치면 같은 후보를 이어 가는 것이 아니다. 고친 규칙은 새 버전의 연구
  후보로 다시 동결하고 검증한다.

## 공식 채택 기준

공식 패턴으로 채택하려면 아래 6개를 모두 충족하고, 충족 근거를 문서로 남긴다.

### 1. 역할 명확성

- 무엇을 탐지하거나 분류하는 패턴인지 명확하다.
- 입력과 출력 상태의 의미를 설명할 수 있다.
- 전략·매매 규칙과 역할이 분리되어 있다.

### 2. 기존 패턴과의 차별성·비중복성

- 기존 공식 패턴과 주된 관찰 축이나 역할이 실질적으로 구별된다.
- 같은 가격 데이터를 쓰거나 일부 결과가 겹치는 것은 허용한다. 완전한 무상관은 요구하지 않는다.
- 기존 패턴의 표현만 바꾼 중복 모델이면 안 된다.

"왜 별도의 공식 패턴으로 존재해야 하는가?"에 답할 수 있어야 한다.

### 3. 계약 완결성

최소한 다음이 문서화되어 있다.

- 지표·입력
- 상태·출력
- 임계값 또는 판정 규칙
- 시점 정합성(PIT)과 데이터 계약
- 결측이나 계산 불가 처리
- 버전

### 4. 결정성·재현성

- 같은 입력이면 같은 결과가 나온다.
- 구현이 문서 계약을 재현한다.
- 필요한 수준의 테스트나 봉인으로 현재 계약이 고정되어 있다.

### 5. 목적에 맞는 검증 완료

- 패턴의 목적과 성격에 맞는 검증을 마쳤다.
- 실패 사례, 한계, 적용 범위를 기록했다.
- 검증 방식은 패턴마다 다를 수 있다. 예를 들어 계약 재현 테스트, 사람 판정과의 비교, 별도
  검증 표본, 라벨을 쓰지 않는 구조 점검 등이 있다. 어떤 방식이 필요한지는 패턴의 목적에서
  정한다.
- 사람 판정을 흉내 내는 것이 목적이 아니라면, 사람 판정 일치율은 필수 조건이 아니다.
- 수익률, 최대 낙폭, 손실 억제는 필수 채택 기준이 아니다.

### 6. 현재 권위 확정

채택할 때 최소한 다음이 분명하다.

- 공식 패턴 이름과 버전
- 현재 권위 규격 문서
- 구현 위치
- 현재 운영 상태
- 알려진 한계
- 연구 기록과 현재 기준의 구분

## 공식 채택 절차

1. **연구 후보 정의** — 탐지하려는 상태·구조와 필요성을 정한다.
2. **개념·계약 명세** — 입력, 출력 상태, 데이터 계약, 결측 처리를 문서로 정한다.
3. **규칙·구현 동결** — 검증 전에 규칙, 임계값, 구현을 고정한다.
4. **목적에 맞는 검증** — 검증 방법과 판단 기준을 검증 전에 정하고, 그대로 수행한다.
5. **공식 채택 기준 6개 점검** — 기준별 충족 근거와 미충족 항목을 기록한다.
6. **상태 결정** — 공식 패턴, 보류, 종료 중 하나로 결정하고 이유를 남긴다.
7. **권위 문서 갱신** — 공식 권위 문서와 현재 README를 결정에 맞게 고친다.

## 검증 원칙

- 검증 방법과 판단 기준은 결과를 보기 전에 정한다. 결과를 본 뒤 과거 검증 기준을 소급해
  바꾸지 않는다.
- 패턴별 세부 수치 기준이 필요하면 각 패턴의 검증 계획에서 사전에 정한다. 이 공통 문서에는
  정확 일치율, 1단계 이내 일치율, 사람 판정 일치율 같은 고정 임계값을 두지 않는다.
- 한 번 쓴 별도 검증 표본은 같은 목적의 재검증에 다시 쓰지 않는다.
- 불리한 결과와 한계도 채택 결정 기록에 그대로 남긴다.

## 기존 패턴과의 관계

이 문서는 기존 패턴의 현재 상태를 다시 판정하지 않는다. Pattern A, Pattern A FAST, Pattern B의
현재 상태는 [패턴 안내](README.md)와 각 패턴 문서의 표기를 따른다. 기존 패턴에 이 기준을
적용하는 판단은 별도 작업에서 한다.

## 문서 관리

이 문서는 패턴마다 복사하지 않고 프로젝트 전체에서 하나만 유지한다. 패턴 채택 절차가 실제로
바뀔 때만 수정한다. 과거 패턴의 채택·보류·종료 기록을 나중에 현재 기준에 맞게 다시 쓰지
않는다.

이 문서는 패턴 연구를 느리게 만드는 규정집이 아니다. 필요한 검증만 하고, 명확한 결론이
나오면 다음 단계로 진행한다.
