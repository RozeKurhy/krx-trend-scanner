# Pattern B 사람 판정 기준 V01

> 상태: 설계 단계. 이 문서는 사람이 차트를 보고 Pattern B 상태를 판정하는 원칙만
> 정한다. 실제 표본, 실제 판정값, Feature 계산, 임계값은 아직 없다.

## 목적

사람 판정 기준(Human Ground Truth)은 다음 질문에만 답한다.

> 평가 시점까지의 가격 차트만 보았을 때, 이 종목은 자기 장기 가격 사이클에서
> 얼마나 침체 또는 과열되어 있는가?

다음 질문에는 답하지 않는다.

- 앞으로 오를 것인가? 지금이 바닥이나 천장인가?
- 지금 사야 하는가, 팔아야 하는가?
- 좋은 회사인가, 저평가 기업인가, 망할 회사인가?
- Pattern A 상승 전환이 나왔는가?

사람 판정은 미래 수익률 평가도, 매매 판단도, 투자 매력도 판정도 아니다.

## 판정 값

[Pattern B 개념 기준](../spec/README.md)의 상태 후보 5개를 의미 그대로 사용한다.

| 판정 값 | 사람이 차트에서 받는 인상 |
|---|---|
| `DEEP_DEPRESSED` | 장기 가격 사이클의 명백한 하단 극단. 과거의 일반적인 가격 영역보다 매우 크게 눌려 있고, 단순 조정이 아니라 장기적으로 극단적인 침체로 보인다 |
| `DEPRESSED` | 장기 사이클의 아래쪽. 침체는 분명하지만 극단이라고 단정하기는 어렵다 |
| `NORMAL` | 아래·위 극단으로 보기 어렵다. 침체나 과열 어느 쪽에도 강한 확신이 없다 |
| `OVERHEATED` | 장기 사이클의 위쪽. 가격이 평상시 영역보다 상당히 확장되어 보인다 |
| `EXTREME_OVERHEATED` | 장기 가격 사이클의 명백한 상단 극단. 일반적인 상승을 넘어 자기 역사 대비 매우 크게 확장되어 보인다 |

판정 기준은 질적 인상으로만 적는다. 퍼센트, 이동평균 이격, RSI, 범위 위치 컷오프,
수익률 임계값 같은 수치 기준을 두지 않는다. 사람 판정 기준이 Feature 임계값을
거꾸로 정의하지 않게 하기 위해서다.

### 판정 보류 (`UNCERTAIN`)

`UNCERTAIN`은 사람 판정 작업에서만 쓰는 보조 기록 값이다. Pattern B의 정식 상태
후보가 아니다. 다음 경우에 사용하며, 5개 상태 중 하나를 억지로 고르지 않는다.

- 침체·정상·과열 중 하나를 자신 있게 고르기 어렵다
- 월봉과 주봉의 인상이 크게 충돌한다
- 차트 이력이 부족하거나 구조가 특이해 판정이 불안정하다

## 월봉과 주봉

개념 기준과 같이 월봉을 우선하고 주봉은 보조로만 본다.

- **월봉**: 장기 침체·과열 판정의 중심
- **주봉**: 현재 극단성이 월봉 인상과 일치하는지 확인하고, 월봉만으로 모호할 때
  최근 구조를 보조로 확인

주봉이 월봉보다 우선하는 규칙은 두지 않는다. 월봉과 주봉이 충돌할 때 자동으로
결론을 내는 규칙도 두지 않으며, 필요하면 `UNCERTAIN`으로 기록한다.

## 판정자에게 보여줄 정보와 숨길 정보

판정은 가능한 한 가리고(blind) 진행한다.

| 보여준다 | 숨긴다 |
|---|---|
| 평가 시점까지 완료된 월봉 가격 차트 | 평가 시점 이후의 모든 가격과 수익률 |
| 평가 시점까지 완료된 주봉 가격 차트 | 종목명, ticker |
| | 실적·Fundamentals, 시가총액 |
| | 외국인·기관 수급, Relative Strength |
| | Pattern A / A FAST 상태 |
| | Pattern B Feature 값, 백분위, 임계값 |
| | 표본 선정 시 붙인 분류(어느 상태 후보로 뽑혔는지) |
| | 백테스트 결과 |

판정 화면의 차트에는 Pattern B Feature 후보를 덧씌우지 않는다. MA24·MA40 선,
범위 위치 표시, 고점 대비 하락 폭 수치, 백분위 수치 등은 판정이 끝난 뒤 Feature
적합성 검토 단계에서만 공개한다.

## 가격 차트 원칙

Pattern B는 가격 사이클 패턴이므로 사람 판정도 가격만 본다. V01에서는 거래량,
거래대금 등 추가 패널을 쓰지 않는다.

- 평가 시점 이후 캔들을 표시하지 않는다.
- 진행 중인 월봉·주봉은 쓰지 않고 완료된 기간만 쓴다.
- 조정 가격 사용 여부는 프로젝트의 공식 가격 데이터 계약을 따른다.
- 평가 시점 이후 데이터가 렌더링, 축 범위 계산 등에 간접적으로도 들어가지 않게 한다.

차트 표시 기간, 캔들·라인 표현 방식, 가격 축 표시 방식은 다음 표본 생성 작업에서
정한다.

## Value Trap과의 경계

사람 판정에서도 침체 상태와 망가진 회사를 구분하지 않는다. 장기간 계속 하락한
종목이라도 차트가 명백한 장기 침체 극단이면 `DEEP_DEPRESSED`로 판정할 수 있다.
생존 위험이나 Value Trap 판단은 향후 별도의 적격성·위험 판단 층(Eligibility / Risk
Layer)의 문제다.

판정자는 다음 이유로 침체 판정을 낮추거나 표본에서 제외하지 않는다.

- “이 회사는 망할 것 같다”
- “너무 오래 떨어졌다”
- “이런 종목은 사고 싶지 않다”

## 판정 기록 형식

실제 표본 작업에서 쓸 최소 기록 필드다.

| 필드 | 의미 |
|---|---|
| `sample_id` | 종목명을 숨긴 익명 표본 ID |
| `as_of` | 판정 기준일 |
| `label` | 5개 상태 후보 중 하나 또는 `UNCERTAIN` |
| `confidence` | `HIGH` / `MEDIUM` / `LOW` |
| `note` | 판정 이유를 짧게 기록 |

`note`에는 Feature 이름이나 숫자 없이 차트에서 받은 인상만 적는다.

> 예: 장기 범위의 하단 극단에 머물러 있고 월봉·주봉 모두 침체 인상이 강함

## 표본 선정 원칙

표본이 한쪽 상태에 몰리지 않도록 다음 유형이 모두 포함되게 구성한다.

- 명백한 침체 후보
- 침체와 정상의 경계로 보이는 후보
- 일반적인 정상 후보
- 과열 후보
- 극단적 과열 후보

평가 시점 이후 성과를 보고 좋은 사례나 나쁜 사례를 고르지 않는다. 표본 수와
종목·날짜 목록은 다음 작업에서 정한다.

## Feature 적합성 검토와의 순서

이 문서는 Feature 후보를 다시 정의하지 않는다. 후보는
[개념 기준의 Feature 후보](../spec/README.md#feature-후보)를 참조한다.

검토는 다음 순서를 지킨다.

1. 사람 판정 결과를 먼저 봉인한다.
2. 그 뒤 Feature 값을 계산한다.
3. Feature가 사람 판정과 어떤 관계인지 진단한다.

Feature 결과를 본 뒤 사람 판정 결과를 Feature에 맞게 고치지 않는다.

## 미확정 항목

- 표본 수, 종목·날짜 목록, 판정 기준일 분포
- 차트 표시 기간, 캔들·라인 표현, 가격 축 표시 방식
- 판정자 수와 판정자 간 불일치 처리 방식
- Feature 산식, 임계값, 자동 판정 규칙
