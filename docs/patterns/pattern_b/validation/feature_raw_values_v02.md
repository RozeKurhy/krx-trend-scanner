# Pattern B 별도 검증 표본 V02 원시 지표값

> 상태: 36개 표본의 유지 지표 3개 원시값 계산·봉인 완료. 상태 판정 규칙 V01 적용과
> 사람 판정 V02와의 비교는 아직 하지 않았다.

## 목적

[별도 검증 표본 V02](holdout_v02_protocol.md) 36개(`PBHOLD_001`~`PBHOLD_036`)에 대해
[지표 선택 V01](feature_selection_v01.md)의 유지 지표 3개 원시값을 계산해 `sample_id`
기준으로 고정한다. 다음 단계의 1회 평가는 이 값을 그대로 쓴다.

- 사람 판정 V02는 이 계산 전에 봉인했다([사람 판정 V02](human_ground_truth_v02.md)).
- 계산에는 사람 판정 결과, 상태 판정 규칙, 임계값을 쓰지 않았다.

## 계산 조건

- 지표: `36M_RANGE_POSITION`, `MONTHLY_MA24_DISTANCE`, `52W_RANGE_POSITION`
- 산식: [지표 계약 V01](../spec/feature_contract_v01.md)의 계산 함수
  `compute_pattern_b_features_v01(daily, as_of)`를 그대로 썼다. 이 함수는 7개 지표를 함께
  계산하지만, 결과 파일에는 유지 지표 3개만 남겼다.
- 표본 대응: 봉인된 별도 검증 표본 비공개 대응표에서 종목코드와 기준일을 읽었다.
  대응표의 SHA-256이 [holdout_v02_seal.json](holdout_v02_seal.json)과 같은지 먼저 확인했다.
- 가격: Repository V2 조정 가격 일봉을 기준일까지만 요청했다.
- 이력 시작일: 차트 묶음과 같이 기준일을 포함하는 PIT COMMON 종목 구간의 시작일이다.
  다른 종목 구간과 이어 붙이지 않는다. 유지 지표 3개는 최근 36개월·24개월·52주 완료 봉만
  쓰므로 시작일이 값에 영향을 주지 않는다.
- 완료된 봉: 지표 계약 V01과 같다(월말·금요일 마감 기준, 기준일 이후 봉 없음, 거래정지
  기간은 봉을 만들지 않음).

## 검증

36개 모두 다음을 확인했다.

- 요청 끝 날짜가 기준일과 같고, 마지막 일봉이 기준일 이하다.
- 마지막 월봉·주봉 날짜가 차트 묶음을 만들 때 기록한 날짜와 같다. 즉 사람이 본 차트와 같은
  봉에서 계산했다.
- 기준일 이후 최대 365일까지 추가 데이터를 요청해 다시 계산했다(365일은 요청 범위다).
  36개 모두 실제로 기준일 이후 거래일이 포함된 입력을 받았고, 그 입력으로 다시 계산해도
  유지 지표 3개 값이 같았다(불일치 0개). 실제 기준일 이후 데이터는 최소 57거래일, 최대
  248거래일이었다. 60거래일 미만 9개, 234거래일과 239거래일 각 1개, 240거래일 이상
  25개다.
- 세 값 모두 유한한 숫자이고 계산 불가 상태가 없다. 범위 위치 2개는 0~1 안에 있다.

표본별 이력 범위, 마지막 봉 날짜, 봉 개수는 기준일을 드러내므로 비공개 실행 기록
(`artifacts/pattern_b_holdout_v02/private/feature_raw_run_v02.json`, Git 미포함)에만 둔다.
