# Pattern B 지표 계약 V01

> 상태: Pattern B 지표 산식·PIT 계약 V01 확정. [개념 기준](README.md)의 지표 후보 7개를 원시값으로
> 계산하는 방법만 정한다. 가중치, 임계값, 점수, 자동 상태 판정은 정하지 않는다.
> 이 계약은 [사람 판정 V01](../validation/human_ground_truth_v01.md) 결과를 보지 않고
> 정했다.

계산 코드: `src/trend_scanner/patterns/pattern_b_features_v01.py`
(`compute_pattern_b_features_v01(daily, as_of)`)

## 공통 데이터 계약

- 입력은 Repository V2의 조정 가격(adjusted) 일봉이다. `high`, `low`, `close`를
  사용하며, 조정 가격을 얻을 수 없으면 비조정 가격으로 대체하지 않고 실패한다.
- 처리 순서는 다음과 같다.
  1. 평가 기준일(`as_of`) 이후 일봉을 모두 버린다.
  2. 남은 일봉을 검증한다. 값이 없거나 유한하지 않거나 0 이하이거나
     `low <= close <= high`를 어기면 계산하지 않고 오류를 낸다.
  3. 완료된 봉만 만든다.
- 완료된 봉: 월봉은 월말(`MonthEnd`), 주봉은 금요일 마감(`W-FRI`) 기준이며,
  봉의 달력상 마지막 날이 `as_of` 이하일 때만 완료로 본다. 집계는 고가 최대, 저가
  최소, 종가 마지막 값이다. [차트 묶음 V01](../validation/chart_pack_v01.md)과 같은
  규칙이다.
  - 따라서 월의 마지막 거래일이 `as_of`여도 달력상 월말이 그 뒤라면(예: 금요일
    2024-08-30) 그 달은 아직 완료로 보지 않는다. 금요일이 휴장인 주도 같다.
- 거래정지 등으로 거래가 전혀 없던 기간은 봉을 만들지 않는다. 가짜 봉, 앞 값
  채우기, 보간, 0 가격을 넣지 않는다.
- 아래 “최근 N개”, `t-12`, `t-26` 같은 창과 간격은 달력 기간이 아니라 **완료된 봉의
  개수**로 센다. 거래정지가 끼면 창이 달력상 더 긴 기간을 덮는다.
- 기호: `t`는 최신 완료 봉, `C = close_t`. 값은 모두 소수(decimal)로 저장한다.
  예: `+0.20`은 20% 위.

## 지표 산식

| 지표 | 시간축 | 필요한 봉 | 산식 |
|---|---|---|---|
| `36M_RANGE_POSITION` | 월봉 | 36 | `(C - L36) / (H36 - L36)`, `L36 = min(low)`, `H36 = max(high)` (최근 36개) |
| `MONTHLY_MA24_DISTANCE` | 월봉 | 24 | `C / mean(close[t-23..t]) - 1` |
| `12M_RETURN_HISTORICAL_PERCENTILE` | 월봉 | 37 | 아래 백분위 계약, `R12_t = close_t / close_(t-12) - 1` |
| `36M_HIGH_DRAWDOWN` | 월봉 | 36 | `C / max(high) - 1` (최근 36개) |
| `52W_RANGE_POSITION` | 주봉 | 52 | `(C - L52) / (H52 - L52)`, `L52 = min(low)`, `H52 = max(high)` (최근 52개) |
| `WEEKLY_MA40_DISTANCE` | 주봉 | 40 | `C / mean(close[t-39..t]) - 1` |
| `26W_RETURN_HISTORICAL_PERCENTILE` | 주봉 | 79 | 아래 백분위 계약, `R26_t = close_t / close_(t-26) - 1` |

범위 위치는 보통 `0 ~ 1`, 고점 대비 하락 폭은 `-1 < 값 <= 0`, 백분위는 `0 ~ 100`이다.

## 백분위 계약

- 비교 분포는 현재 관측치를 **제외**하고, 현재 완료 봉보다 앞서 끝난 유효한 수익률
  전체로 만든다(누적 분포, expanding). 고정 길이 이동 창을 쓰지 않는다.
- 최소 비교 표본: 12개월 수익률 24개, 26주 수익률 52개. 그래서 필요한 봉은 월봉
  12 + 24 + 1 = 37개, 주봉 26 + 52 + 1 = 79개다.
- 백분위는 동률을 절반으로 세는 중간 순위(mid-rank) 방식이다.

```text
percentile = 100 * (count(reference < current) + 0.5 * count(reference == current)) / len(reference)
```

- 분포는 호출자가 넘긴 이력 전체에 걸쳐 누적되므로, 결과는 이력의 시작일에 따라
  달라진다. 실제 계산에서는 이력 시작일을 고정해 기록해야 한다(예: Repository V2
  로더의 기본 시작일 `1900-01-01`, 즉 확보된 전체 이력).

## 계산 불가 처리

계산할 수 없을 때는 값을 비우고(`None`) 사유를 남긴다. `0.5` 같은 임의 값을 넣지
않는다.

| 상태 | 뜻 |
|---|---|
| `OK` | 계산 완료 |
| `INSUFFICIENT_BARS` | 필요한 완료 봉 수가 부족하다 |
| `FLAT_RANGE` | 범위 위치 창의 최고가와 최저가가 같다 |
| `INSUFFICIENT_REFERENCE` | 백분위 비교 표본이 최소 개수보다 적다 |

입력 검증 실패는 상태가 아니라 오류(`PatternBFeatureInputError`)로 처리한다.
