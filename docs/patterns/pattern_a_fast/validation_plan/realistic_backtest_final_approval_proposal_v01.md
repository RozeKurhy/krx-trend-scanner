## 1. 목적과 범위

이 문서는 FastCore 현실적 백테스트의 남은 공통 조건에 대해 최종 추천안 하나씩을 제시하고, 사용자가 승인하거나 수정할 수 있게 하는 문서다. 이 문서의 추천안은 사용자 승인 전에는 실행계약이나 구현 기준으로 승격하지 않는다.

이번 작업에서는 백테스트, 성과 계산, 실행 코드·러너·아티팩트 변경, 데이터 수집, `pytest`, V2 규칙 변경을 수행하지 않는다. 현재 문서는 승인 전 단계이므로 실행 계약을 확정하지 않는다.

## 2. 이미 확인된 기준

다음 항목은 이번 승인 대상에서 제외하고 기존 공식 기준을 그대로 유지한다.

- 저장소는 `MarketDataRepositoryV2`를 사용한다.
- 과거 시점의 PIT 유니버스는 역사적 기준으로 채운다. 현재 종목 목록을 과거 시점에 방송하지 않는다.
- 가장 가까운 날짜로 대체하지 않으며, 필요한 결측은 명시적으로 실패·예외 처리한다.
- 전략은 `PATTERN_A_FAST_FINAL_STRATEGY_V02`를 사용하고 V2 규칙을 변경하지 않는다.
- 신호는 완료된 관측값으로 확정하고 `NEXT_LOCAL_TRADING_DAY_OPEN`에서 체결한다.
- 동일 종목 동시 보유, 피라미딩, 같은 시가의 청산 후 재진입은 허용하지 않는다.
- 역사적 매도 거래세는 실제 체결일과 시장에 따른 공식 세율을 적용하며, 매수에는 적용하지 않는다. 거래세 상태는 `확인됨`이다.

## 3. 최종 추천안 승인표

아래 표의 `사용자 승인`이 모두 승인되기 전에는 추천안을 실행 기준으로 사용하지 않는다.

| 항목 | 최종 추천안 | 근거 | 사용자 승인 |
|---|---|---|---|
| 매수 수수료 | 매수 체결금액의 **0.015%** | 특정 계좌 복제가 아닌 국내 온라인 거래의 단순 공통 가정으로 사용한다. 공식 온라인 수수료 범위의 상단에 맞춰 재현성을 확보한다. | 대기 |
| 매도 수수료 | 매도 체결금액의 **0.015%** | 매수와 같은 고정률을 적용해 방향별 비대칭을 만들지 않는다. 역사적 매도 거래세는 별도로 적용한다. | 대기 |
| 매수 슬리피지 | 기준 체결 시가에 **0.10%**를 가산 | 거래량 충격이나 유동성별 동적 모델 없이, 지나치게 낙관적이지 않은 고정 가정으로 둔다. | 대기 |
| 매도 슬리피지 | 기준 체결 시가에 **0.10%**를 차감 | 매수와 대칭인 고정 가정으로 두고, 실제 매매 규모에 따른 동적 충격은 모델링하지 않는다. | 대기 |
| 초기자본 `C0` | **100,000,000원** | 정규화만으로는 현금 부족을 검증할 수 없으므로 절대 금액을 사용한다. 사용자 계좌 복제가 아닌 재현 가능한 연구 자본이다. | 대기 |
| 1회 진입 투자금 `q` | **5,000,000원** | 고정 거래금액으로 진입별 비교를 단순화하고 `C0`의 5%로 설정한다. 기존 200M/5M를 자동 승계하지 않는다. | 대기 |
| 종목별 최대 투자금·비중 | **5,000,000원, 초기자본의 5%** | 동일 종목의 추가 매수 없이 한 종목 집중도를 제한한다. | 대기 |
| 최대 동시 보유 `N` | **20개** | `q × N = C0`가 되도록 설정해 모든 슬롯이 채워졌을 때 초기자본을 넘는 주문을 만들지 않는다. | 대기 |
| 현금 부족 | 부분 체결하지 않는다. 필요한 `q`와 슬롯을 확보하지 못한 진입은 `SKIPPED_CASH_UNAVAILABLE` 또는 `SKIPPED_POSITION_LIMIT`으로 기록한다. 동일 시가 배치는 아래 일괄 규칙을 적용한다. | 부분 체결이라는 추가 가정과 처리 순서에 따른 편향을 제거한다. | 대기 |
| 매도대금 재사용 | 같은 시가에는 재사용하지 않는다. 매도 이벤트가 반영된 **다음 평가 가능한 로컬 거래일 시가**부터 재사용한다. | 매도와 신규 매수의 순서에 따라 같은 날 가용 현금이 달라지는 것을 막는다. | 대기 |
| 동일 시가 신규 진입 순서 | 신규 신호를 하나의 일괄 배치로 취급한다. 해당 배치의 모든 `q`와 슬롯을 감당할 수 있을 때만 모두 진입하고, 부족하면 모두 건너뛴다. 성과·점수·수익률 우선순위는 만들지 않는다. 기록 순서는 `시장 구분|종목 식별자`의 정렬을 사용하되 자본 배분에는 영향을 주지 않는다. | 종목코드 순차 우선이나 성과 기반 우선순위로 인한 임의의 자본 배분을 피하면서 결과를 결정적으로 재현한다. 청산은 항상 신규 진입보다 먼저 처리한다. | 대기 |
| `UNRESOLVED` 처리 | 가격 또는 생애주기 근거가 없는 포지션은 `UNRESOLVED`로 남기고 포지션 수준 예외로 기록한 뒤 실행은 계속한다. 해당 포지션을 임의 평가하거나 조용히 제외하지 않으며, 실행 상태는 `INCOMPLETE_REQUIRES_REVIEW`로 표시하고 영향 금액과 예외 수를 함께 보고한다. | 한 포지션의 자료 결측 때문에 전체 표본을 버리지 않으면서도, 결측을 정상 성과에 섞어 왜곡하지 않는다. 예외가 있는 결과는 최종 승격 대상이 아니다. | 대기 |
| 회전율 산식 | `T = (Σ 매수 거래금액 + Σ 매도 거래금액) / C0` | 거래금액은 비용과 세금 차감 전 명목금액으로 계산하고, 거래세·수수료·슬리피지는 별도 비용 항목으로 보고한다. | 대기 |
| 회전율 보고 단위 | 전체기간 배수 `T`와 백분율 `100T%`를 함께 보고하며 **연환산하지 않는다**. | 기간 자체를 보존하고 연환산에 따른 추가 해석을 만들지 않는다. | 대기 |
| 시장별 벤치마크 | `KOSPI COMMON → KOSPI 지수 1001`, `KOSDAQ COMMON → KOSDAQ 지수 2001`을 전략과 같은 기간·최종 평가 의미론으로 비교한다. | ROADMAP의 시장 대응 기준과 현재 시장 유니버스를 그대로 재사용한다. | 대기 |
| 혼합 포트폴리오 벤치마크 | 단일 혼합 벤치마크를 만들지 않고 **KOSPI·KOSDAQ 결과를 분리 보고**한다. | 사전 시장별 자본 배분이 없는 상태에서 임의의 가중치를 만들지 않는다. | 대기 |
| 공통 시장 국면 게이트 | 공통 필수 진입 게이트를 추가하지 않는다. `PERMITTED_REGIME`은 V2 전략 내부 규칙으로만 유지한다. | 새로운 공통 국면 모델이나 필터를 도입하지 않고 동결된 V2 의미론을 보존한다. | 대기 |
| 강건성 검증 범위 | V2 임계값 탐색 없이 **연도, KOSPI/KOSDAQ, 종목 집중도, 대형 수익 종목 집중도, 대형 손실 집중도**만 최소 구간으로 보고한다. 집중도는 상위·하위 10개 거래 기여를 기준으로 고정한다. | 강건성과 집중위험을 확인하는 데 필요한 최소 범위만 남기고 임계값 조합 탐색과 과최적화를 막는다. | 대기 |

## 4. 승인 후 최소 보고 형식

전체 결과와 위 강건성 구간별로 다음 지표만 보고한다.

- 거래 횟수
- 총수익률
- MDD
- 평균·중앙 보유기간
- 투자 노출도
- 회전율
- cutoff 시점 미청산 포지션 수(`OPEN_AT_CUTOFF`)

`UNRESOLVED`가 하나라도 있으면 실행 결과에 예외 수, 영향 금액, `INCOMPLETE_REQUIRES_REVIEW` 상태를 함께 표시한다. `UNRESOLVED`를 정상 종가나 0으로 바꾸지 않는다.

## 5. 공식 수수료 자료의 최소 확인

수수료는 전 증권사 조사가 아니라 주요 온라인 거래 사례 2건만 확인했다.

- [키움증권 국내투자 시작하기·주식 FAQ](https://www1.kiwoom.com/h/domestic/stock/VStockMainView?dummyVal=0): HTS·홈페이지 현금 주식매매 수수료 0.015%를 안내한다.
- [미래에셋증권 고객자산배분전략 공식 자료](https://securities.miraeasset.com/public/hks4412/003/StrategyAugust.pdf): 다이렉트 계좌 국내주식 온라인 기본 수수료 0.014%를 안내한다.

두 자료는 특정 사용자의 계좌·이벤트 조건을 재현하는 근거가 아니라, 온라인 국내주식 수수료의 현실적 범위를 확인하는 참고다. 따라서 최종 공통 가정은 계산이 단순하고 재현 가능한 0.015%로 둔다. 거래세는 위 승인표의 선택 항목이 아니며, 이미 확인된 역사 세율을 적용한다.

## 6. 승인 전 금지 범위

사용자 최종 승인 전에는 다음을 수행하지 않는다.

- FastCore 또는 Julia 백테스트 실행과 성과 계산
- V2 임계값 탐색, 새 필터, 새 시장 국면 모델 추가
- 실행 코드, 러너, PIT 로더, V2 문서, 결과 아티팩트 변경
- 외부 API 호출과 `pytest`
- 이 문서의 추천안을 공통 조건 또는 최종 실행계약으로 승격

승인 이후에도 별도 실행계약을 먼저 만들고, 승인된 항목만 구현·검증 범위에 포함한다.
