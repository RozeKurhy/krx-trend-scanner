# 백테스트 공통 실행 원칙

## 1. 문서 역할

이 문서는 특정 전략의 성과나 V2·Julia 비교 결과를 정의하지 않는다. 새로운
전략 또는 기존 전략 개선 백테스트를 실행할 때 공통으로 지켜야 하는 데이터,
시점, 체결, 비용, 현금, 평가, 무결성 원칙을 정의한다.

초기 자본, 종목별 투자금액, 동시 보유 수, 기간, benchmark, 전략 규칙과 같은
실험 변수는 백테스트마다 사전에 명시한다. `200M / 5M / 40종목`은 과거
FastCore 비교에서 사용한 값일 뿐 모든 백테스트의 영구 기본값이 아니다.

## 2. 항상 유지하는 공통 원칙

### 2.1 데이터와 Point-in-Time

- 공식 `MarketDataRepositoryV2`와 현재 데이터 원천 계약을 사용한다.
- 역사적 유니버스는 해당 기준일의 PIT 분모를 사용한다. 현재 종목 목록을
  과거 날짜 전체에 방송하지 않는다.
- 신호·투자 적합성·전략 상태에는 기준 시점 이후의 자료를 사용하지 않는다.
- 완료된 일봉·주봉·월봉만 사용한다. 진행 중인 기간의 값을 완료된 값처럼
  사용하지 않는다.
- 조정 OHLC, 원자료 거래량·거래대금·시가총액의 날짜 의미론을 사전에 고정하고
  비교 전략 사이에서 임의로 다른 원천을 선택하지 않는다.
- 비영업일, 동결 달력 밖 날짜, 중복 행, 미래 행, 날짜 집합 불일치는 명시적인
  실패 또는 격리 상태로 기록한다.

### 2.2 결측과 대체

- 필요한 데이터가 없으면 `DATA_UNAVAILABLE`, `UNRESOLVED` 또는 실행 계약에
  정의된 실패 상태로 기록한다.
- 가장 가까운 다른 날짜 값, 현재 값, forward-fill, interpolation, 0 대체,
  임의 proxy를 조용히 사용하지 않는다.
- 결측을 제외하고 계산할 수 있는 경우에도 어떤 필드를 제외했는지와 판정
  의미를 결과에 남긴다.

### 2.3 신호와 체결

- 신호가 확정된 시점과 실제 체결 시점을 분리한다.
- 신호는 완료된 관측값으로 확정하고, 체결은 사전에 정한 다음 거래일·시가·종가
  의미론을 따른다.
- 미래의 체결가·고가·저가를 신호 계산에 사용하지 않는다.
- 동일 시가의 청산 후 재진입, 중복 포지션, 피라미딩은 허용 여부를 사전에
  정하고 결과에 명시한다. 전략 계약이 금지하면 수행하지 않는다.

### 2.4 비교 공정성

- 비교하는 전략에는 같은 데이터, PIT 분모, 기간, 비용·세금·슬리피지, 평가
  의미론을 적용한다.
- 전략별 진입·보유·청산 규칙은 각 전략 계약에서만 가져온다. 공통조건 문서가
  전략 규칙이나 추가 필터를 몰래 주입하지 않는다.
- Fundamentals, 투자 적합성, 시장 국면, 종목 순위와 같은 추가 축은 포함 여부,
  기준일, 임계값을 백테스트마다 명시한다. 별도 선언 없이 자동 적용하지 않는다.

### 2.5 PIT 진입 자격 구간과 실제 종목 생명주기

PIT COMMON 관측구간의 `effective_from`/`effective_to`는 관측 범위와 신규 후보·진입
자격을 나타내며, 실제 종목 생명주기나 정산일을 뜻하지 않는다. 표준 실행 구간의
`effective_end`는 신호·평가 기준 종료일이고, 체결 지원 구간은 그 뒤의 후속 체결만
지원한다.

| 필드 | 분류 | 근거와 사용 경계 |
|---|---|---|
| 기본정보 원천의 `ISU_CD` | A. 안정 종목 식별 구성요소 | KRX 기본정보 계약에서 표준코드다. 같은 증권의 시장 이전은 같은 정체성으로 결합하고, 다른 표준코드는 같은 단축코드의 재사용 종목과 구분한다. |
| `ticker` | C. 표시·조회 편의 필드 | 기본정보의 `ISU_SRT_CD`가 단축코드다. 일별 거래 원천은 API별 의미에 따라 `ISU_CD`를 단축코드로 쓰므로 원천별 필드 의미를 섞지 않는다. 단축코드만으로 장기 정체성을 정하지 않는다. |
| `market` | C. 상장 시장 속성 | 같은 표준코드의 시장 이전에서 달라질 수 있으므로 안정 종목 식별자에 넣지 않는다. |
| `effective_from`, `effective_to` | B. PIT 관측 구간 메타데이터 | 관측 권위 범위·진입 자격에만 사용하며 안정 종목 식별자나 생명주기 종료일로 사용하지 않는다. |

안정 종목 식별은 같은 증권 발행의 생명주기 안에서 표준 `ISU_CD`를 기준으로 한다. 이는
발행자 전체, 후속·대체 증권 또는 기업 사건 전후 증권이 자동으로 같은 정체성이라는
뜻은 아니다. 로컬 PIT 식별자 해석기는 동일 `ISU_CD`의 시장 이전 구간을 결합하고,
단축코드 재사용은 서로 다른 `ISU_CD`로 분리한다. 현재 저장된 PIT에서 같은 표준코드가
서로 다른 ticker로 이어지는 사례는 관측되지 않았으므로, ticker 변경에 따른 가격 이력
연결은 이 문서만으로 추정하지 않고 별도 확인 대상으로 둔다.

- 신규 후보·진입 신호와 실제 진입 체결은 모두 해당 COMMON 구간 안이어야 한다.
  진입 체결은 실행 구간의 `effective_end`도 넘을 수 없다.
- 이미 진입한 포지션은 COMMON `effective_to` 이후에도 실제 생명주기 근거가 없으면
  실행 구간의 `effective_end`까지 가격과 청산 신호를 추적한다.
- `effective_end`까지 이미 발생한 청산 신호의 다음 거래일 시가 체결은 필요한
  경우 체결 지원 구간에서 허용한다. 체결 지원 날짜의 신호나 신규 진입은 허용하지 않는다.
- 기준 종료일 평가에는 `effective_end`까지 실제 관측된 종가만 사용한다. 가장 가까운 날짜,
  전방 채움 또는 임시값으로 대체하지 않는다.
- 실제 생명주기 종료·정산은 해당 안정 종목 식별자와 개별 사건이 일치하는 별도
  공식 근거 자료로만 판정한다. 사건 연결에는 표준 `ISU_CD`와 원천 문서·사건일·
  유형을 사용하고, `ticker`/`market`/PIT 끝점은 식별 키로 사용하지 않는다.
  정산일이 COMMON 구간 뒤여도 증거를 거부하지 않지만, 실행 구간의 `effective_end` 뒤
  정산은 해당 실행에 적용하지 않는다.

실행별 cutoff와 체결 지원 날짜의 구체 값은 §3.1에서 고정한다. 이 절의 경계 계약은
모든 기간과 전략에 적용한다.

## 3. 백테스트마다 사전에 정하는 변수

다음 값은 공통 원칙이 아니라 실행별 실험 설정이다.

| 범주 | 사전 명시할 값 |
|---|---|
| 자본 | 초기 자본, 종목별 예산, 최대 동시 보유 수, 비중·포지션 한도 |
| 기간 | 평가 시작일, 신호 cutoff, 체결 지원 종료일, 최종 평가일 |
| 전략 | 진입·보유·청산·재진입 규칙, 전략 버전, 적용 상태 |
| 유니버스 | 자산 유형, 시장, PIT 분모, 투자 적합성·기타 필터 적용 여부 |
| 실행 | 체결 가격, 이벤트 순서, 현금 부족, 부분 체결, 동일 시가 처리 |
| 비용 | 매수·매도 수수료, 거래세의 날짜·시장별 스케줄, 슬리피지 |
| 평가 | 미청산 처리, benchmark, CAGR 기준, MDD·노출·회전율 정의 |
| 강건성 | 연도·시장·집중도 등 보고할 분할과 최소 표본 기준 |

설정값은 실행 전에 고정하고, 결과를 본 뒤 유리하게 바꾸지 않는다. 변경이
필요하면 새 실행 또는 명시적인 revision으로 기록한다.

### 3.1 표준 비교 기간 세트

새 전략과 기존 전략 개선안을 비교할 때 아래 다섯 기간을 기본 표준 기간으로
사용한다. 이 표는 **calendar boundary**이며, 전략 규칙·성과 기준·투자 적합성
필터를 정의하지 않는다.

기간 자체의 데이터·계산 가능성과 특정 현재 runner의 실행 준비도는 별도로
판정한다. runner 입력 산출물이나 코드가 기간을 지원하지 않는다는 이유만으로
표준 기간을 `INVALID`로 처리하지 않는다. 결과에는 두 판정을 분리해 기록한다.

| ID | 명칭 | Calendar range |
|---|---|---|
| P1 | Long History | 2014-01-01 ~ 2026-08-31 |
| P2-1 | 2021 Fixed | 2021-01-01 ~ 2025-05-31 |
| P2-2 | 2021 Full | 2021-01-01 ~ 2026-08-31 |
| P3-1 | 2022 Fixed | 2022-01-01 ~ 2025-05-31 |
| P3-2 | 2022 Full | 2022-01-01 ~ 2026-08-31 |

각 실행은 검증된 운영 rolling calendar authority(과거 고정 fixture에서는 해당
fixture의 고정 calendar authority)로 calendar start 이상 첫 거래일과
calendar end 이하 마지막 거래일을 resolve하고 결과에 기록한다. P1의 목표
calendar start는 2014-01-01이다. 공식 Repository V2 가격 이력이 2014년을
지원하지 못하는 실행에서는 날짜를 임의 변경하거나 가격을 보간하지 말고,
가장 이른 정상 사용 가능 시작일과 영향 범위를 `P1 effective available start`로
보고한다. 공식 달력 authority가 기간 종료 또는 필요한 execution support까지
포함하지 않으면 뒤 날짜를 추정하지 않고 해당 실행을 차단해 authority 범위와
필요한 최소 갱신을 보고한다.

평가 시작일과 지표 예열용 선행 이력 시작일은 다를 수 있다. 필요한 선행 가격 이력은
평가 구간 밖에서 읽되 평가 시작일을 늦추지 않는다. 기간 종료일은 신호·평가 기준
종료일이다. 다음 거래일 시가 체결이 필요한 경우 그 날짜를 별도 체결 지원 구간으로
확보한다. 이 구간은 종료일 이전에 이미 발생한 신호의 후속 체결에만 사용하며, 기준
종료일 뒤의 신호나 신규 포지션을 만들지 않는다. 기간·기준 종료일·체결 지원 종료일의 구체 값은
실행 전에 정하고, 진입 자격·생명주기 경계는 §2.5를 따른다.

이 표준 기간은 시가총액·최소 거래량/거래대금·펀더멘털 필터를 기본 적용하지
않는다. 단, 전략이 원래 지표 계산에 사용하는 가격·거래량 입력은 전략 계약대로
유지한다. 모든 종목이 전체 기간에 존재해야 하는 것은 아니다. PIT 구간과 실제 종목
생명주기 경계의 상세 계약은 §2.5를 따른다.

강건성 분석은 사용자가 요구했거나 전략 판단에 실제로 필요한 경우에 수행한다.
수행하는 경우에만 연도·시장·거래 집중도 등 분석 범위와 최소 표본 조건을
실행 전에 정한다. 단순 확인 백테스트에 강건성 분석을 자동으로 추가하지 않는다.

## 4. 체결·비용·자금 운용 계약

### 4.1 비용과 세금

- 비교 전략 사이에서 수수료·거래세·슬리피지를 동일하게 적용한다.
- 거래세는 실제 매도 체결일과 시장에 따른 역사적 법정 스케줄을 사용하는지,
  고정값을 사용하는지 실행 전에 명시한다.
- 슬리피지는 기준 체결가에 어떤 방향과 비율로 적용하는지 고정한다.
- 비용은 체결가, 명목 거래금액, 현금흐름, 순수익에 일관되게 반영한다.

### 4.2 부분 체결과 현금 부족

- 부분 체결을 허용하는지 금지하는지 실행 전에 정한다.
- 부분 체결을 금지하면 해당 이벤트를 명시적인 `SKIPPED_*` 사유로 기록한다.
- 현금·포지션 한도 초과 시 우선순위와 이벤트 처리 순서를 사전에 고정한다.
- 같은 시가에 매도한 자금을 신규 진입에 재사용하는지 여부를 사전에 정한다.
- 전략 점수나 결과를 보고 현금 배분 순서를 사후 변경하지 않는다.

### 4.3 이벤트 원장

각 주문·포지션에는 최소한 다음을 남긴다.

- 신호일, 체결일, 평가일
- 기준 가격과 비용·슬리피지 반영 체결가
- 수량, 명목 거래금액, 수수료, 세금, 슬리피지
- 체결 전후 현금과 보유 수량
- 포지션 식별자, 진입·청산 사유
- 미청산·결측·실패·건너뜀 상태와 사유

## 5. 미청산 포지션과 성과 집계

- 평가 기간 종료 시 미청산 포지션은 `OPEN_AT_CUTOFF`로 종료 거래와 분리한다.
- 기준일 종가를 확보할 수 없으면 다른 날짜로 대체하지 않고 `UNRESOLVED` 또는
  실행 실패로 처리한다.
- 미청산 평가를 실제 매도 체결로 간주하지 않는다. 실현 수익률, 매도 비용,
  거래세, 회전율 포함 여부를 사전에 정의한다.
- 기본적으로 필요한 핵심 지표는 총수익률, CAGR, MDD, 거래 수, 평균 보유기간,
  승률, 비용 총액, 미청산 포지션 수다.
- 다음 상세 지표는 백테스트 목적에 필요할 때만 추가한다: MDD 기간·회복 여부,
  평균·최대 노출도, 회전율, 손익비, `UNRESOLVED` 영향 금액, 연도·시장·거래
  집중도 분할 분석.
- 동일한 지표 정의를 비교 전략에 적용한다.

## 6. Benchmark와 robustness

- benchmark와 비교기간은 실행별로 사전에 명시한다.
- 혼합 포트폴리오에서 임의의 단일 합성 benchmark를 만들지 않으며, 필요한
  경우 시장별 benchmark를 분리해 보고한다.
- 강건성 분석을 수행하는 경우, 연도·시장·거래 집중도 등 분석 범위와 최소
  표본 조건을 사전에 정한다.
- 결과를 본 뒤 특정 구간만 선택하거나 불리한 거래를 제거하지 않는다.
- 파라미터 grid search, 대규모 튜닝, 결과 기반 threshold 조정은 별도 연구로
  분리하고 현재 실행의 공통조건에 포함하지 않는다.

## 7. 실행시간 규칙

전체 백테스트는 가급적 1시간 내외, 최대 약 1시간 30분을 목표로 한다. 2시간
이상 걸리는 구조를 기본값으로 받아들이지 않는다.

전체 실행 전에 다음 순서를 지킨다.

1. 대표 샘플로 짧은 샘플 실행을 한다.
2. 샘플당 처리시간과 대상 수를 측정한다.
3. 전체 대상 수를 기준으로 예상 실행시간을 계산한다.
4. 전체 실행 전에 예상시간을 보고한다.
5. 예상시간이 과도하면 확인된 병목만 최소 범위로 줄인다.

정확도를 희생하는 임의 표본 축소, 필요 없는 대규모 병렬화, 복잡한 캐시
시스템과 대규모 리팩터링은 기본 해법으로 사용하지 않는다. 최적화는 실제
병목과 효과를 확인한 뒤 최소 변경으로 수행한다.

## 8. 실행 전 체크리스트

- 전략 ID와 규칙 문서가 고정됐는가?
- 평가기간, cutoff, 지원 종료일, 최종 평가일이 고정됐는가?
- PIT 유니버스와 데이터 원천이 고정됐는가?
- PIT 진입 자격 구간과 실제 종목 생명주기·정산 경계를 구분했는가?
- 완료된 기간만 사용하도록 확인했는가?
- 결측·대체·실패 의미론이 고정됐는가?
- 체결 시점, 이벤트 순서, 부분 체결, 현금 부족 처리가 고정됐는가?
- 비용·세금·슬리피지가 비교 전략에 동일한가?
- 초기 자본·동시 보유·benchmark·보고 지표가 명시됐는가?
- 샘플 실행과 예상시간 계산을 먼저 했는가?
- 결과를 본 뒤 규칙을 바꾸지 않도록 실행 기록을 봉인했는가?
